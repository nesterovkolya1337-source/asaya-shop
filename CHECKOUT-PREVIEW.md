# Тестовое оформление ASAYA

Добавлен полный локальный путь: серверный каталог → корзина → подтверждённый вход → расчёт доставки → сохранение заказа → история заказов. Оплата не выполняется, реальное отправление не создаётся.

## Что изменилось

- Отдельный флаг NEXT_PUBLIC_TEST_CHECKOUT=true включает тестовую корзину и оформление только в режиме серверного каталога. Без него серверная витрина остаётся доступной для просмотра.
- Корзина содержит только идентификаторы карточек и количества, сохраняется в sessionStorage текущей вкладки. Цена и доступность берутся заново из сервера; промокоды и обещание бесплатной доставки из деморежима не применяются.
- Недоступный товар остаётся видимым в корзине и блокирует оформление. Количество ограничивается остатком и 100 единицами на позицию.
- Расчёт доставки требует сессии, Origin и CSRF. Клиент передаёт состав корзины и адрес; цену и склад выбирает DeliveryProvider. Результат проверяется, сохраняется с пользователем, составом корзины и сроком действия. Вызов поставщика ограничен четырьмя секундами.
- DisabledDeliveryProvider используется по умолчанию: недоступный расчёт возвращает 503, бесплатный тариф не подставляется.
- После расчёта показывается итог, затем вводятся вымышленные контакты и подтверждается тестовое оформление. Согласие записывается как test-v1, marketing=false; это не утверждённые документы рабочего магазина.
- Создание заказа повторно проверяет цену, остаток, пользователя, склад и срок расчёта. Заказ, снимки данных и резерв сохраняются одной транзакцией.
- Перед отправкой сохраняется номер попытки, отдельно для каждого аккаунта. Повтор использует тот же ключ; после перезагрузки сначала запрашивается результат прошлой попытки. При неопределённом ответе доступны проверка и повтор этой же отправки.
- Телефон, адрес, имя, код входа и токены сессии не записываются этой формой в хранилище браузера. Контакты находятся в памяти формы и в серверном снимке подтверждённого заказа.
- После подтверждения сервера показываются номер и сумма, очищается соответствующая корзина и предлагается открыть историю. Изменённая за время ожидания корзина автоматически не удаляется.

## Новые маршруты

- POST /api/store/v1/delivery/quotes — доверенный серверный расчёт.
- GET /api/store/v1/checkouts/by-key/:key — результат собственной попытки.
- POST /api/store/v1/checkouts — существующее создание заказа, теперь подключённое к форме; требует Idempotency-Key.

## Воспроизводимый изолированный стенд

Архив — накопительное дополнение к копии исходного проекта на fa2164a, включая предыдущие этапы. Распакуйте его в отдельную копию проекта. Изображения, node_modules, база и исходный XLSX не включены.

Нужен Node.js 22.6+ (проверено на 24.19). В первом PowerShell из каталога backend:

```powershell
npm ci
$env:ASAYA_PREVIEW_DELIVERY='enabled'
npm run preview:checkout
```

Этот явно выбранный скрипт создаёт отдельную временную PostgreSQL, не читает DATABASE_URL, не импортирует настоящий ассортимент и работает 15 минут. Единственный товар CHECKOUT-FIXTURE привязан к карточке шампуня, тестовая цена — 250 ₽, остаток — 20, доставка — 100 ₽. Это вымышленные значения.

Во втором PowerShell из корня копии проекта:

```powershell
npm ci
$env:NEXT_PUBLIC_CATALOG_SOURCE='backend'
$env:NEXT_PUBLIC_TEST_CHECKOUT='true'
$env:ASAYA_BACKEND_ORIGIN='http://127.0.0.1:3100'
npm run dev -- --hostname 127.0.0.1 --port 3200
```

Откройте http://127.0.0.1:3200/catalog/, добавьте шампунь и перейдите к оформлению. Войдите через checkout-preview@example.test: код появится только в терминале изолированного стенда. Никаких писем или SMS он не отправляет. После входа вернитесь к оформлению, заполните вымышленные данные, рассчитайте доставку и создайте тестовый заказ.

Для проверки отказа доставки запустите стенд без ASAYA_PREVIEW_DELIVERY. При перезапуске создаётся новая пустая тестовая база и потребуется новый вход. Завершение — Ctrl+C в обоих терминалах. Временные кластеры остаются в игнорируемом backend/.test-data для диагностики.

Собранная витрина проверяется командами npm run build и npm run start -- --hostname 127.0.0.1 --port 3200 с теми же переменными. После смены флагов требуется пересборка.

Штатный backend/server.ts по-прежнему использует отключённые внешние отправители и запрещает NODE_ENV=production. Подключение поставщиков выполняется отдельно через интерфейсы OtpSender и DeliveryProvider; тестовый скрипт для запуска магазина не подходит.

## Проверено

- 27 тестов backend на настоящем временном PostgreSQL и 15 клиентских тестов прошли.
- Проверены суммы в копейках, отключённый и некорректный поставщик доставки, устаревший расчёт, запрет тарифа из браузера, CSRF, изоляция пользователя, повтор и восстановление результата, отсутствие двойного резерва.
- В браузере пройден путь от каталога до истории: вход, сохранение корзины после полной загрузки страницы, отказ отключённой доставки, успешный тестовый расчёт, заказ ASAYA-10001 на 350 ₽, очистка корзины и сохранённые суммы 250 + 100 ₽ в истории.
- TypeScript, ESLint и сборки серверного режима и статического деморежима проверены.

## Что остаётся для рабочего магазина

Реальные OTP, оплата/возвраты, СДЭК и интеграция YCP, администраторские действия, эксплуатация и развёртывание. Цены, остатки, ассортимент и юридические тексты ожидают согласования. 11 утверждённых связей сохранены; шесть спорных связей и наборы не переутверждались. Вопросы Максу остаются в отдельном списке.
