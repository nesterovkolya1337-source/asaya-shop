# История заказов ASAYA — локальный этап

В личный кабинет добавлены список своих заказов, просмотр состава и стоимости, отдельные статусы заказа/оплаты/доставки и отмена неоплаченного заказа. Всё работает через существующий backend в режиме `NEXT_PUBLIC_CATALOG_SOURCE=backend`.

## Что готово

- После серверного входа показывается «Мои заказы». Есть загрузка, пустой список, ошибка с повторной попыткой, обновление и «Показать ещё».
- История загружается по 20 заказов, новые сверху. Курсор привязан к заказу текущего пользователя; сравнение даты и идентификатора выполняется в PostgreSQL без потери точности даты.
- Карточка заказа показывает номер, дату и итоговую сумму. Подробности содержат сохранённые названия товаров, количества, цены, стоимость доставки и общий итог. Изменение текущего каталога не переписывает историю.
- Для draft-заказа с оплатой pending/failed доступна отмена с подтверждением внутри интерфейса. Сервер повторно проверяет владельца и статус под блокировкой, освобождает резерв один раз и сохраняет отмену.
- Оплаченный заказ нельзя отменить этой кнопкой. Это не запуск возврата денег. Если деньги пришли после отмены, статусы показываются раздельно с предложением обратиться в службу заботы.
- Интерфейс не показывает отмену до подтверждения сервером. При неопределённом результате из-за сети предлагается обновить список.
- Без сессии список недоступен. Чужой заказ и чужой курсор не открываются; пользователь берётся из cookie, а не из параметра запроса. Отмена требует Origin и CSRF.
- При выходе или обнаружении истёкшей сессии история убирается с экрана. Заказы не записываются в localStorage.
- Страница «Статус заказа» в серверном режиме направляет в личный кабинет вместо проверки по непроверенному email.

## Запуск

Используйте инструкции `CATALOG-PREVIEW.md` и `AUTH-PREVIEW.md`: локальный backend на 127.0.0.1:3100, витрина на 127.0.0.1:3200, PUBLIC_ORIGIN совпадает с адресом витрины. Откройте `/account/` и войдите через настроенный OTP-провайдер.

Новые HTTP-маршруты проксируются только к локальному backend:

- GET `/api/store/v1/orders` — список, необязательные cursor и limit (1–50, по умолчанию 20).
- GET `/api/store/v1/orders/:id` — подробности, суммы и canCancel.
- POST `/api/store/v1/orders/:id/cancel` — отмена собственного неоплаченного draft-заказа.

В штатном запуске OTP-провайдер всё ещё отключён. Для реального входа нужен его адаптер; история не создаёт обходной способ авторизации. Новые покупки, внешняя оплата и доставка ещё не подключены.

Архив содержит полный backend и все изменения витрины относительно исходной версии `fa2164a`, включая предыдущие этапы. Это дополнение к отдельной копии исходного проекта, без изображений и установленных зависимостей. Исходный проект и опубликованный сайт не менялись. Новых миграций на этом этапе нет.

## Проверено

- 23 теста backend на реальном временном PostgreSQL и 11 клиентских тестов — все прошли.
- Среди проверок: одинаковые даты заказов при постраничной загрузке, появление нового заказа между страницами, изоляция пользователей, запрет подмены user_id, CSRF отмены, повторная отмена и проверка сумм.
- В браузере проверены вход, история трёх вымышленных заказов, состав и суммы, подтверждение отмены, обновление статуса отменённого заказа, отсутствие отмены у оплаченного заказа и скрытие истории после выхода.
- Проверки TypeScript, ESLint и сборка серверного режима прошли.

В браузерной проверке использовалась только временная тестовая база с товаром «Тестовый товар — не для продажи». Реальные заказы, платежи, остатки и согласования ассортимента не менялись.
