# Товарный фид Яндекса

Добавлен YML/XML-фид из базы магазина: `GET /api/store/v1/yandex/feed.xml`. Генерация происходит при запросе, данные не кэшируются. Внешняя публикация и добавление адреса в кабинет Яндекса не выполнялись.

Формат сверён 07.09.2026 с официальными описаниями [фида](https://yandex.ru/support/merchants/ru/connect/form-feed), [элементов магазина](https://yandex.ru/support/merchants/ru/elements/shop) и [товаров](https://yandex.ru/support/merchants/ru/offers). Используются цена в рублях, currencyId=RUR, вес в килограммах и размеры в сантиметрах. В каждом предложении явно стоит is_checkout_enabled=false до отдельного включения и приёмки покупки через Яндекс. Сам фид кнопку на сайте не устанавливает.

## Какие данные попадают в фид

Только активные разрешённые товары с утверждённой ценой и связью витрины, опубликованным содержимым и положительным доступным остатком на настроенных активных складах YCP. Черновик редактирования не используется. Наборы, требующие компонентного списания, исключены.

Для попадания нужны один однозначный offerID в аккаунте YCP, название не длиннее 150 символов, описание, категория, ссылка на подходящее изображение и вес/габариты. Описание ограничивается первыми 3000 символами. Символы XML экранируются; недопустимые управляющие символы удаляются. Фото выбираются из опубликованного изображения и галереи, максимум десять. Проверяется формат ссылки; реальная доступность, размер и пропорции удалённых изображений пока не проверены.

Цена преобразуется из копеек без округления: 50001 → 500.01. oldprice выводится только при целой цене в рублях и подходящей скидке. Если необязательная старая цена не подходит, текущая цена остаётся в фиде. Никакие реальные цены, остатки или товарные соответствия на этом этапе не утверждались.

Фид публичный после настройки и не содержит токенов, адресов складов, покупателей или причин исключения товаров. Причины доступны только в локальном отчёте команды экспорта. Если настройки feed отсутствуют, HTTP возвращает 503.

## Стабильные идентификаторы

Используется существующая таблица product_external_ids с provider=ycp и выбранными accountId/environment. GET фида не пишет в БД. Для подготовки отсутствующих ID есть отдельная команда: по умолчанию она показывает план, --apply применяет его транзакционно и пишет аудит. Новый ID имеет вид asaya-UUID_товара и не зависит от названия или цены.

Существующий единственный ID сохраняется. Несколько ID у одного товара помечаются как неоднозначность: товар не выдаётся, а система не выбирает новый ID молча. Конфликт нового ID с другим товаром отменяет весь пакет. Повтор применения не создаёт дублей. Подготовка этих технических связей не публикует товар и не разрешает продажу.

## Настройка и команды

В приватный файл YCP_SETTINGS_FILE добавьте feed с name (краткое название магазина) и company (подтверждённое полное наименование владельца). Например структура полей: `"feed": {"name":"ASAYA","company":"ПОДТВЕРЖДЁННОЕ НАИМЕНОВАНИЕ"}`. Это шаблон, не реальные реквизиты. Нужны прежние настройки accountId, environment=test, publicOrigin и склады. Отсутствие priceUnit/vat блокирует проверку корзины YCP, но не выгрузку фида в рублях с выключенной покупкой.

Из каталога backend после сборки и настройки окружения:

```sh
npm run yandex:feed -- prepare
npm run yandex:feed -- prepare --apply
npm run yandex:feed -- export /absolute/path/to/new-feed.xml
```

Для локального .env можно запускать `node --env-file=.env dist/scripts/yandex-feed.js prepare` и аналогично остальные команды. DATABASE_URL и YCP_SETTINGS_FILE обязательны. Экспорт не перезаписывает существующий файл. В отчёте выводятся число включённых товаров и причины пропуска. Для HTTP-фида нужны также прежние парные YCP_TOKEN/YCP_SETTINGS_FILE. Данные из примеров не следует загружать как реальный ассортимент.

Новых миграций нет, используются 001–014. Изменён только backend. Production по-прежнему выключен; для реального Яндекса ещё требуется доступный HTTPS-маршрут, утверждённые реквизиты и проверка кабинетом.

## Проверки

Добавлены семь тестов: подготовка и повтор ID, проверка того же offerID через YCP-корзину, точные цены и единицы, XML-экранирование, исключение неподготовленных товаров, сохранение существующих связей и их изоляция по аккаунтам, публичный HTTP без утечки закрытых данных. Синтетический фид дополнительно прочитан независимым XML-парсером .NET: проверены структура, значение цены и восстановление спецсимволов в названии. Это не заменяет валидацию фида Яндексом.

Полный набор backend: 103 из 103 тестов прошли без пропусков; компиляция прошла. Клиентские тесты и сборки сайта повторно не запускались, так как клиентский код не менялся.
