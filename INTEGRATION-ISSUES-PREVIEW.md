# ASAYA: проверка интеграции в админке сайта

Добавлен раздел «Проверка интеграции» по пункту 16 ТЗ. Он показывает ошибки обработки событий и историю сигналов для сверки платежей, возвратов и отмен. Есть фильтры, страницы по 20 событий, обновление и переход к карточке заказа.

Для события доступны время создания, состояние очереди, количество попыток обработки, безопасная категория ошибки и время, с которого разрешён повтор. Это не обещание автоматического запуска: обработчик должен быть подключён и работать. В технических подробностях — ID события, идентификаторы сессии и заказа Яндекса, если они связаны с заказом ASAYA.

Сигналы для сверки сохраняются видимыми после обработки очереди: статус done не подтверждает фактический возврат денег или решение вопроса. Раздел ничего не повторяет, не возвращает деньги и не меняет заказы. Произвольные тексты ошибок, payload, ключи, токены и контакты не выдаются. Неизвестные типы ошибок показываются общей безопасной категорией.

API: GET /api/admin/v1/integration-issues?filter=all|errors|review&cursor=UUID. Требуется активная сессия администратора; ответы не кэшируются. Новых миграций нет, остаётся 001–015.

Ограничение: это диагностика сохранённых событий очереди. Ошибки входящих запросов, которые не создали событие или заказ, пока доступны только в техническом журнале запросов. Полная связь request ID с событием и отдельный просмотр таких ошибок ещё не реализованы; пункт 16 закрыт частично.

Проверки: права и отключённый администратор, фильтры, переход по страницам без дублей, сохранение истории сверок, исключение секретов и клиентская проверка ответа. Полный набор тестов, линтер, проверка типов и сборка выполняются для этого этапа.

Работа выполнена в копии проекта. Боевой сайт, кабинет Яндекса и исходный проект не изменялись.
