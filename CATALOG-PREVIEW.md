# Локальная витрина с серверным каталогом

Добавлен отдельный режим просмотра каталога через backend. Он не оформляет заказы и не подключает оплату или доставку. Серверный вход в этом режиме описан в `AUTH-PREVIEW.md`; внешний отправитель OTP ещё не подключён. Исходный проект и опубликованный сайт не изменялись.

## Поведение

- Товары загружаются через `/api/store/v1/products`. Сервер возвращает только активные товары с утверждённой ценой, разрешением продажи и утверждённой связью с карточкой.
- Названия, описания и изображения берутся из соответствующих карточек витрины; цены в копейках и остатки — только из ответа сервера. Неизвестные или повторные карточки и некорректные суммы вызывают ошибку загрузки всего каталога.
- При запуске, пустом ответе, ошибке или восьмисекундном таймауте показывается соответствующее состояние. После ошибки можно повторить загрузку. Демоданные не подставляются.
- Демо-вход, демо-оформление, добавление в корзину и локальные правки товаров отключены в этом режиме. Сохранённые демо-цены, остатки, корзина и email из localStorage не читаются и не перезаписываются. Избранное действует только в текущем сеансе страницы.
- На текущем импорте каталог пуст: 11 связей утверждены, но настоящие цены, остатки и разрешения продажи ещё не согласованы. Новых цен и остатков этот этап не создаёт.

## Запуск

Нужен Node.js 22.6+ (проверено на 24.19) и локальный PostgreSQL. Подготовьте backend по его README: зависимости, сборка, миграции, импорт исходного XLSX и `approve:mappings -- --apply`. Затем запустите его с `.env` на `127.0.0.1:3100`. Секреты остаются только в backend/.env.

В отдельном PowerShell, из корня рабочей копии:

```powershell
npm ci
$env:NEXT_PUBLIC_CATALOG_SOURCE='backend'
$env:ASAYA_BACKEND_ORIGIN='http://127.0.0.1:3100'
npm run dev -- --hostname 127.0.0.1 --port 3200
```

Откройте `http://127.0.0.1:3200/catalog/`. Next.js пересылает каталог, маршруты входа, просмотра и отмены заказов к локальному backend; CORS и публикация API не требуются. Адрес backend ограничен localhost/127.0.0.1. `NEXT_PUBLIC_BASE_PATH` учитывается в запросе. Сам режим и этот прокси предназначены для локальной проверки. История заказов описана в `ORDERS-PREVIEW.md`.

Для проверки собранной версии вместо dev выполните `npm run build`, затем `npm run start -- --hostname 127.0.0.1 --port 3200` с теми же переменными. Режим фиксируется при сборке: после переключения переменной требуется новая сборка. В режиме backend статический export отключён, нужен процесс Next.js.

Чтобы вернуться к прежнему статическому деморежиму, уберите обе переменные из текущего терминала и пересоберите проект. По умолчанию продолжает действовать `output: export`; существующие файлы развёртывания не менялись. Это не переключение рабочего магазина на реальные заказы.

## Проверки

- 20 тестов backend прошли на настоящем временном PostgreSQL, включая фильтрацию неутверждённых связей, импорт исходного каталога и утверждение 11 пар.
- 3 теста адаптера каталога: серверные суммы и остатки, пустой ответ, некорректные/неизвестные/повторные карточки. Команда: `npm run test:catalog`.
- TypeScript, ESLint, сборка режима backend и прежний статический export прошли. Для последующей небольшой правки заголовка подборки товаров повторно проверены TypeScript и ESLint.
- В браузере проверены загрузка реального импортированного каталога без цен, ошибка при выключенном API, повторная попытка, закрытые checkout и личный кабинет.

Следующие этапы: серверный вход с выбранным OTP-провайдером, корзина и оформление с доверенной котировкой доставки, подключение оплаты. Они требуют отдельного завершения; просмотр каталога не означает готовность магазина к приёму заказов.
