Эксплуатация от root:

```sh
cd /opt/asaya-catalog/current
docker compose -f deploy/catalog/compose.yaml ps
sh deploy/catalog/backup.sh
docker compose -f deploy/catalog/compose.yaml restart db api web
docker compose -f deploy/catalog/compose.yaml up -d --wait --wait-timeout 90 db api web
```

Не применять down -v: это удалит постоянный том. Обновлять API и web вместе из подготовленного релиза. Для отката только публичных маршрутов исходный Caddyfile сохранён в /opt/asaya-catalog/Caddyfile.before; после восстановления содержимого в /opt/asaya-shop/deploy/Caddyfile выполнить caddy validate и caddy reload в asaya-shop-caddy-1. Данные новой базы при этом сохраняются.

В /opt/asaya-shop Caddyfile изменён для нового раздела; до работы там уже был посторонний untracked-файл true. Он не изменялся и не удалялся. Старый asaya-autodeploy.timer активен, но его скрипт останавливает обновление при грязном дереве. Перед последующим обновлением основной витрины необходимо согласовать эту конфигурацию с репозиторием. Коммиты и push в этом этапе не выполнялись.
