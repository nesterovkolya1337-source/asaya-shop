# Визуальный редактор ASAYA

Состояние на 8 сентября 2026: реализация подготовлена и проверена локально. Новая версия редактора ещё не установлена на asaya.ru.

## Что доступно

В админке появился раздел «Редактор сайта». В центре находится настоящая страница ASAYA, слева — её блоки, справа — поля выбранного блока. Нажатие на блок в предпросмотре открывает его настройки. Правки сразу отражаются в предпросмотре.

- Страницы: главная, о бренде, вопросы и ответы, доставка и оплата, служба заботы, где купить.
- Заголовки, тексты, фотографии, подписи, кнопки и ссылки; карточки внутри блоков.
- Загрузка JPG, PNG и WebP до 6 МБ через существующее хранилище изображений.
- Добавление блоков из 15 готовых типов, изменение порядка, скрытие и повторное включение. До 30 блоков и до 30 карточек в блоке.
- Предпросмотр компьютера и телефона.
- Сохранение черновика, отдельная публикация, возврат черновика к последней опубликованной версии.
- Защита от потери правок при переходе и одновременном редактировании двумя сотрудниками.

Товары, артикулы и размещение подборок продолжают редактироваться в разделе «Товары». Шапка, подвал, юридические страницы и служебные экраны покупки пока не входят в редактор страниц. Макет готовых типов блоков задан дизайном сайта; редактор меняет их содержимое и порядок, без ввода HTML или кода.

## Хранение и доступ

Миграция `016_site_pages.sql` добавляет отдельную таблицу страниц. Товары и остатки она не меняет. Черновик и опубликованная версия хранятся раздельно. Публичный API возвращает только опубликованную страницу без скрытых блоков. Загрузка медиа использует существующий сервис обработки изображений.

Изменения доступны действующим администраторам через существующие сессии, проверку Origin и CSRF. Сохранение, публикация и восстановление проверяют номер версии страницы и пишутся в журнал. При конфликте чужие правки не перезаписываются.

Предпросмотр передаёт черновик в iframe только в пределах того же origin. Доступ к черновикам через публичный API не появляется. Токены и данные сессий в адрес предпросмотра не передаются.

## Подготовка установки

Для появления правок на основном сайте необходимо обновить **и API, и админку, и статическую витрину**. Обновление только `/manage` не меняет текущую витрину.

1. Сделать обычную резервную копию базы и сохранить текущие версии образов.
2. Собрать API с миграцией 016 и выполнить существующую процедуру миграций. Использовать реальные секреты только из серверного хранилища.
3. Собрать админку через `deploy/catalog/Dockerfile.web`. Он включает два общих файла контракта контента. Режим каталога и выключенное оформление заказов сохраняются.
4. Собрать статическую витрину через корневой `Dockerfile`, передав build argument `NEXT_PUBLIC_SITE_CONTENT=backend`. Префикс витрины остаётся пустым. Caddy уже направляет `/api/store/v1/*` в API.
5. Проверить вход, загрузку каждой страницы в редактор, работу медиа под `/manage`, сохранение черновика и отсутствие изменений публичной версии до публикации.

Данные исходных страниц включены в код как начальная версия. До первой публикации, а также при недоступности сервиса контента на новом открытии, сайт показывает эту исходную версию. Опубликованный контент загружается в браузере; статический HTML и метаданные страниц пока остаются исходными. Для индексации изменяемого контента без выполнения JavaScript потребуется следующий этап — серверная выдача публичных страниц.

## Локальный демонстрационный режим

Открытый предпросмотр работает с отдельными тестовыми данными в памяти и отмечен соответствующей плашкой. Его правки не попадают на asaya.ru и сбрасываются при перезапуске тестового сервиса. Обработчик демонстрации находится вне приложения, не включён в пакет и не должен устанавливаться на сервер. В рабочей конфигурации `NEXT_PUBLIC_EDITOR_PREVIEW` не задаётся.
