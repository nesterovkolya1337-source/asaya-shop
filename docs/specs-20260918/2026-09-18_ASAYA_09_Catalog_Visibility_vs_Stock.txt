ASAYA — STOREFRONT ТЗ
09 · Видимость товара ≠ наличие на складе
18 сентября 2026 года
Главное правило. Stock отвечает только за возможность купить товар. Visibility/published/active отвечает за то, показывается ли товар на сайте. Эти состояния нельзя связывать автоматически.

1. Цель
Исправить логику storefront так, чтобы опубликованные товары всегда оставались видимыми на сайте независимо от складского остатка. Нулевой остаток должен отключать покупку, но не скрывать товар, карточку или витрины.
2. Закрытая бизнес-логика
Состояние
Что должно происходить
published/active/visible = true, stock > 0
Товар виден и доступен к покупке.
published/active/visible = true, stock = 0
Товар виден везде, но недоступен к покупке. На PDP показывается «Нет в наличии».
published/active/visible = true, stock unknown/stale
Товар остаётся видимым. Возможность покупки определяется безопасной stock-policy отдельной задачи; visibility не меняется.
published/active/visible = false
Товар может быть скрыт с storefront независимо от stock.

3. Где товар обязан оставаться видимым при stock = 0
Главная страница и товарные витрины/подборки.
Блоки «Новинки», «Бестселлеры» и другие существующие selections.
Категории Face / Body / Hair и иные опубликованные категории.
Каталог и поиск, если эти функции уже существуют.
Прямая URL-карточка товара (PDP).
Рекомендации и связанные товарные блоки, если товар опубликован и подходит по существующей логике.
4. Карточка товара при stock = 0
PDP продолжает открываться как обычно.
Фото, название, описание, состав, характеристики, отзывы и прочий контент не скрываются.
В зоне покупки явно показывается статус «Нет в наличии».
Добавление в корзину должно быть недоступно.
Нельзя подменять «Нет в наличии» на скрытие кнопки без понятного статуса для пользователя.
При восстановлении stock > 0 товар автоматически снова становится доступным к покупке без ручной перепубликации.
5. Корзина
Связь с ТЗ 08. Если товар уже лежал в корзине и затем stock стал 0, применяется отдельное ТЗ 08 Cart Out-of-Stock UX: товар остаётся видимым в корзине, становится приглушённым, получает «Нет в наличии», исключается из purchasable total и не передаётся в Yandex Checkout.

6. Что Codex НЕ должен делать
Не фильтровать storefront query по stock > 0, если цель запроса — показать опубликованные товары.
Не менять published/active/visible автоматически при stock = 0.
Не удалять товар из подборки/категории только из-за отсутствия остатка.
Не удалять PDP route и не отдавать 404 только из-за stock = 0.
Не менять дизайн товарных витрин, карточек или категорий сверх статуса доступности.
Не создавать отдельную frontend-копию stock как новый source of truth; использовать backend stock-layer.
7. Технический принцип
Storefront должен разделять минимум два независимых свойства:
visibility/publication: можно ли показывать продукт пользователю;
purchasability/availability: можно ли сейчас добавить/оформить продукт исходя из stock.
Если текущий код использует stock для фильтрации product list/query, изменить только эту зависимость: published products должны попадать в выдачу независимо от quantity, а stock использоваться для вычисления purchase state.
8. Acceptance criteria
Проверка
Ожидаемый результат
Опубликованный SKU, stock = 0
Есть на главной/в соответствующей витрине и категории.
Открытие PDP stock = 0
Карточка открывается; видно «Нет в наличии»; купить нельзя.
Stock 0 → 5
Тот же товар без перепубликации снова становится доступным к покупке.
Stock 5 → 0
Товар не исчезает; purchase state меняется на «Нет в наличии».
published=false, stock > 0
Товар скрыт согласно publication logic; stock сам по себе его не публикует.
Товар уже в корзине и stock → 0
Поведение строго по ТЗ 08.
Витрины при всех stock=0
Сами блоки с товарами продолжают отображаться; они не должны исчезать из-за нулевых остатков.

9. STOP condition
После выполнения. Показать, где именно ранее stock использовался для скрытия товара, какие запросы/components исправлены, какие тесты добавлены. Commit + push → отчёт → STOP. Не переходить к checkout/YCP или другим ТЗ автоматически.

Правила для Codex
Работать только в области этого файла. Не выполнять следующие ТЗ автоматически.
Не переосмысливать закрытые бизнес- и архитектурные решения.
Не использовать stock=0 как признак скрытия/снятия товара с публикации.
Не делать unrelated refactor и не менять утверждённый дизайн витрин, категорий, header или PDP вне описанных изменений.
После реализации: релевантные tests/build → commit → push → отчёт LOCAL/GITHUB/PRODUCTION → STOP.
Production не менять без отдельного разрешения.
