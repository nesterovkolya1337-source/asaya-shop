ASAYA — FRONTEND / CART ТЗ
08 · Поведение товара без остатка в корзине
17 сентября 2026 года
Цель. Если товар уже находится в корзине, но фактический остаток по единому stock-layer стал 0, пользователь должен видеть этот товар, понимать причину недоступности и не иметь возможности оформить его. Недоступная позиция не должна влиять на сумму доступного заказа и не должна передаваться в Yandex Checkout.

Источник истины. Статус доступности берётся только из того же backend stock-layer ASAYA, который используется в Admin → Аналитика → Остатки и в YCP checkout/basket/check. Frontend не имеет отдельного источника stock.

1. Область задачи
Только UX/логика корзины для товара, который стал недоступен по stock.
Не менять механизм получения остатков из CDEK/CDEK Fulfillment.
Не менять YCP server methods, кроме использования итогового purchasable basket в следующем YCP-шаге.
Не создавать shipment/order в CDEK.
Не делать redesign всей корзины.
2. Поведение недоступной позиции
Товар остаётся видимым в корзине и не удаляется автоматически.
Карточка/строка товара визуально приглушается: меньшая opacity/контраст в рамках текущей дизайн-системы, без полного redesign.
Показывается явный статус «Нет в наличии».
Недоступное количество нельзя увеличить.
Недоступная позиция не входит в сумму товаров, доступных к оформлению.
Недоступная позиция не передаётся в Yandex Checkout.
Пользователь может удалить её из корзины вручную обычным способом.
Если stock снова становится > 0, товар автоматически возвращается в активное состояние при очередном актуальном backend-check и снова участвует в сумме/оформлении.
3. Если доступно меньше, чем уже лежит в корзине
Отдельный случай. Если товар есть на складе, но quantity в корзине превышает фактически доступное количество, нельзя молча считать всю позицию доступной. Backend должен вернуть фактический допустимый quantity. UI должен явно показать, что доступное количество изменилось, и скорректировать purchasable quantity согласно общей cart/YCP логике. Не придумывать отдельные правила, противоречащие checkout/basket/check.

4. Итоги корзины и CTA
Subtotal/итог рассчитывается только по доступным к оформлению товарам и допустимому quantity.
Доставка/порог бесплатной доставки рассчитываются по той же purchasable сумме, а не по визуально оставшимся недоступным позициям.
Если есть хотя бы одна доступная позиция, CTA «Оформить заказ» остаётся доступной и оформляет только purchasable basket.
Если все позиции недоступны, CTA оформления блокируется.
При полностью недоступной корзине показать короткое объяснение, например: «Сейчас в корзине нет товаров, доступных к оформлению». Точный текст можно адаптировать к существующему tone of voice без изменения смысла.
5. Актуализация stock в корзине
При открытии корзины backend должен дать актуальное состояние товаров из stock-layer.
Перед фактическим запуском Yandex Checkout доступность должна быть повторно server-side проверена.
Нельзя полагаться только на состояние, сохранённое в localStorage/DOM при добавлении товара несколько минут или часов назад.
Если stock изменился между открытием корзины и нажатием CTA, frontend должен получить authoritative результат backend и обновить UI до перехода либо обработать официальный ответ YCP без продажи недоступного quantity.
6. Состояния
Состояние
Поведение
stock > 0 и qty допустим
Обычная активная позиция; участвует в total и checkout.
stock = 0
Приглушена; «Нет в наличии»; исключена из total и checkout.
stock unknown/missing
Не трактовать автоматически как доказанный 0. Использовать безопасное состояние общей stock-архитектуры и не продавать на основании выдуманного значения.
cart qty > available qty
Показать изменение доступного количества и привести purchasable quantity к допустимому значению по backend/YCP contract.
stock снова > 0
Позиция снова активна после получения актуального backend state.

7. Acceptance criteria
Товар со stock=0 остаётся в корзине визуально, но не входит в итоговую сумму.
Товар со stock=0 не попадает в payload, из которого запускается Yandex Checkout.
При всех недоступных товарах оформить заказ невозможно.
При смеси доступных и недоступных товаров checkout работает только с доступными позициями.
После восстановления stock позиция снова становится активной без необходимости заново добавлять товар.
Frontend status совпадает с backend stock-layer; отдельного frontend stock source нет.
Изменение не ломает существующее удаление товара, изменение quantity и дизайн корзины за пределами описанных состояний.
8. Связь с другими ТЗ
Зависит от 01 — CDEK/CDEK Fulfillment → ASAYA Stock Source & Sync.
Зависит от 02 — Admin → Аналитика → Остатки для ручной проверки source data.
Связано с 03 — YCP checkout/basket/check: YCP должен получать тот же authoritative stock; данный файл описывает только cart UX.
Связано с 05 — кнопка «Оформить заказ»: перед запуском Yandex Checkout должна использоваться только purchasable basket.
9. Правила для Codex
Работать только с поведением корзины, описанным в этом файле.
Не менять архитектуру stock и не вводить новый источник остатков.
Не делать redesign корзины заодно.
Не удалять unavailable item автоматически.
Не придумывать YCP fields: интеграционный payload остаётся задачей соответствующего YCP ТЗ.
