## Результат сверки

Действующий обработчик уже соответствует заданию; переписывание алгоритма не потребовалось. Добавлены пояснение политики в коде и расширенная проверка полного HTTP-ответа в production-режиме на временной базе.

`POST /api/v1/checkout/basket/check` принимает `items[{id,quantity}]`, `offers_id_from_merchant_center`, `locality`, `is_health_check`. Первый запрос сопоставляет offer ID с учётом аккаунта и окружения, последующие используют SKU. Приблизительного поиска по названию нет.

Ответ использует документированные `regular_price`, `final_price`, `id`, `warehouses[{id,available_quantity}]`, размеры в миллиметрах и вес в граммах, ссылки, характеристики, варианты и `vat`. Новых полей `availability`, `stockState` или stock snapshot в YCP не добавлено.

`available_quantity` — текущий предел покупки. Запрошенное количество не задаёт остаток: при доступной 1 и запросе 2 возвращается предел 1. Проверка сама не резервирует товар; существующий обработчик создания сессии отдельно проверяет и резервирует количество атомарно.

Цены берутся из утверждённых записей backend. Дополнительные поля цены/остатка в запросе и некорректное количество отклоняются. Настройки единиц цены и НДС сохранены; дробные копейки не округляются молча в режиме целых рублей.

## Общий источник и неизвестный остаток

Один запрос БД читает цены и доступные остатки через общую `asaya_stock_limit`, учитывая локальные резервы. Синхронных обращений к СДЭК и отдельного кеша YCP нет.

Сохранена ранее зафиксированная безопасная политика:

| Состояние | YCP | Админка / корзина ASAYA |
| --- | --- | --- |
| Подтверждённый положительный остаток | Допустимое количество после локальных обязательств | Измеренный остаток и количество к покупке различаются |
| Подтверждённый ноль | Предел покупки 0 | Известный ноль / «Нет в наличии» |
| Нет синхронизации или SKU отсутствует | Предел 0 либо пустой список складов при отсутствии записи баланса | Количество источника null / наличие не подтверждено |
| Устаревшая выгрузка или ошибка | Предел покупки 0 | Последнее измерение сохранено с stale/error; корзина показывает неподтверждённое наличие |

Нулевой предел покупки в YCP не означает измеренный физический ноль. Контракт не предоставляет отдельного поля unknown; внутренние сведения о причине сохраняются. Нового бизнес-решения о подмене unknown нулём не принималось.

Админка показывает количество из выгрузки, продажа дополнительно учитывает резервы и потреблённые единицы. При измеренных 10 и резерве 3 администратор видит 10, а каталог/YCP разрешают 7. Для YCP дополнительно применяется область обслуживаемого региона и настроенных складов.

ТЗ 08 уже исключает недоступные строки из запуска Чекаута. При изменении остатка после перехода basket/check возвращает текущий предел по каждому запрошенному товару, включая 0. Строки ответа не удаляются произвольно. UX и алгоритм перехода в этой задаче не менялись.
