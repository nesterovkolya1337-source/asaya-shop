# События заказа для проверки сотрудником

В карточке заказа админки сайта добавлен блок «События для проверки». Он показывает сохранённые сигналы: оплату после отмены, подтверждение Яндекса после отмены, необходимость сверки возврата денег или снятия блокировки средств, физического возврата товара и оплаты при получении.

Сигналы извлекаются для конкретного заказа, сгруппированы по типу с датой первого события. Обработка сообщения очередью не считается решением вопроса: записи остаются видимыми и при статусе очереди done. Это история сигналов, а не список незакрытых задач. Отметки о проверке сотрудником, автоматические возвраты и оприходование товара этим этапом не добавлены. Сверка выполняется в кабинете Яндекса и на складе.

API карточки для сотрудника возвращает только kind и createdAt; содержимое очереди, диагностические ошибки и данные подключения не передаются. Покупательский API не изменён. Проверка активного сотрудника остаётся обязательной. Клиент проверяет допустимые типы и даты, не принимает дубликаты и отбрасывает лишние поля. Отсутствующее поле старого ответа трактуется как пустой список для совместимости.

Проверки: полный набор бэкэнда — 110 тестов, клиента — 34 теста, все без ошибок и пропусков. Проверены реальные события частичного выкупа на временной PostgreSQL, изоляция заказов, отсутствие данных очереди в ответе, сохранение сигналов после обработки, отказ покупателю и отключённому сотруднику. Сборка, TypeScript и ESLint прошли. В браузере на изолированном тестовом заказе подтверждено отображение сигнала оплаты после отмены.

Для повторения предпросмотра: в backend установить ASAYA_PREVIEW_ADMIN=enabled, ASAYA_PREVIEW_ORDERS=enabled, ASAYA_PREVIEW_REVIEW=enabled и запустить npm run preview:checkout. Это временная база на 15 минут с вымышленными товарами и платежами, без внешних действий. Временные реквизиты сотрудника выводятся локально при запуске.

Исходный проект не менялся. Новых миграций нет: 001–014. Подключение настоящего кабинета Яндекса и запуск продаж остаются отдельным этапом.
